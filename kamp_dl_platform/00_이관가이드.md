# dl.kamp-ai 이관 가이드 — IWG 프레스가드 라이트 v1.2

제출 소스의 핵심(분할·블록 교차검증·8개 후보 비교·부스팅 선정·확률보정·시험 평가·오류분석·추론 엔진)을 **그대로** dl.kamp-ai(T3Q.ai) 학습·추론 파이프라인에 올리는 순서입니다. 각 단계 옆 [매뉴얼 n]은 함께 받은 매뉴얼 번호입니다.

> v1.2.1 패키지: 추론 결과의 `reason`에 경보 근거(정상 99% 초과 신호, 하부 진동 정지 시 센서 확인 안내, 경보 진입 시점 SHAP 주요 기여)가 추가되었습니다. 학습 파이프라인·모델·판정은 v1.2.0과 같습니다. 실제 플랫폼 실행 기록은 `platform_run_result/`(v1.2.0)에 있습니다.

```
실행환경(Docker) → 학습 알고리즘(소스 zip) → 데이터셋(CSV zip) → 학습 모델 설계·실행 → 추론 모델 배포 → 추론 테스트
```

## 0. 준비물 (이 폴더)
| 폴더 | 파일 | 쓰는 곳 |
|---|---|---|
| 1_실행환경 | requirements.txt, Dockerfile (막히면 planB_python310) | 프로젝트 설정 > 실행환경 관리 |
| 2_학습알고리즘 | PressGuard_algorithm_v1.2.zip | 프로젝트 설정 > 학습 알고리즘 관리 > 소스 코드 업로드 |
| 3_데이터셋 | press_dataset.zip (원본 CSV 2개) | 학습 플랫폼 > 데이터셋 관리 |
| 4_추론테스트 | 입력창용 JSON, 예시 CSV 2개 | 추론 모델 관리 > 테스트 |

## 1. 프로젝트 만들기 [매뉴얼 1]
- 프로젝트명: `IWG_PressGuard` / 설명: `프레스 유압펌프 이상탐지` (설명 2~30자)

## 2. 실행환경 등록·빌드 [매뉴얼 2]
- **반드시 `t3qai_client==1.1.2`로 고정**(KAMP 운영팀 답변: 최신 1.2.x는 플랫폼 API(v2)와 호환되지 않아 학습이 시작되지 않음)
- 프로젝트 설정 > 실행환경 관리 > `+`
- 실행환경명: `pressguard_py312` / 템플릿: **General** / 설명: `프레스가드 v1.2 학습·추론`
- 상세정보 > **이미지 빌드**: requirements 칸과 Dockerfile 칸을 `1_실행환경`의 두 파일 내용으로 **통째로 교체**
  - `t3qai_client` 줄과 Dockerfile의 '#플랫폼 사용 필요' 아래 3줄은 지우면 안 됩니다(이미 들어 있음)
  - **주의(실제 플랫폼 확인)**: Dockerfile에 `&&`나 `rm -rf`가 들어가면 저장 시 '저장에 실패하였습니다'(서버 400)가 납니다. 명령은 한 줄에 하나씩 `RUN`으로 나눠 쓰세요(제공 파일은 이미 반영). 실행환경명은 `pressguard_py312`처럼 밑줄 사용을 권장
- 저장 → 상세 화면 하단 **빌드** → 상태 '완료' 확인
- 빌드 실패 시(외부 이미지 차단 등): `planB_python310`의 두 파일로 다시 등록. 이 조합도 시험 판정·경보가 제출 결과와 **완전히 같음**을 확인했습니다(점수 차 0).

## 3. 학습 알고리즘 등록 [매뉴얼 3]
- 프로젝트 설정 > 학습 알고리즘 관리 > `+`
- 알고리즘명: `PressGuard_HGB_v1.2` / 카테고리: **Classification** (Anomaly Detection도 가능하나 Classification이 혼동행렬·F1 표시에 유리)
- 실행환경: `pressguard_py312`
- 설명(예): `오프셋 불변 인과특징 11개 + 시간블록 교차검증으로 8개 후보 비교 후 그래디언트 부스팅·Platt 보정 선정. 시험 F1 0.700, 지속경보 F1 0.767`
- 공통 파라미터: 선택하지 않아도 됨(분석 규칙은 코드에 고정)
- 모델 파라미터(선택):
  | 이름 | 기본값 | 의미 |
  |---|---|---|
  | `train_mode` | `full` | `full`=제출 파이프라인 전체 재실행, `bundle`=재학습 없이 제출 모델 배포 |
  | `run_analysis` | `true` | 오류·중요도·점검 우선순위 분석 포함 여부 |
  | `operating_mode` | `standard` | 추론 기본 모드(`unmanned` / `standard` / `screening`) |
- 소스 코드: 알고리즘을 먼저 저장한 뒤 상세 화면 하단 **파일업로드**로 `PressGuard_algorithm_v1.2.zip` 선택(zip은 자동 압축 해제). 업로드 후 목록에 `.t3qai/_runtime_config.yaml`, `train.py`, `inference_service.py`가 최상위에 보이면 정상
- 저장

## 4. 데이터셋 등록 [매뉴얼 4]
- 학습 플랫폼 > 데이터셋 관리 > 등록
- 데이터셋명: `KAMP_소성가공_유압펌프` / `press_dataset.zip` 업로드 → 저장
- 상세 화면에서 `press_data_normal.csv`, `outlier_data.csv` 두 파일이 보이면 정상
- 전처리 모델은 만들지 않습니다. 중복 제거·공백 분할·인과 특징 계산은 학습 코드가 직접 수행하며, 학습 시작 시 원본 SHA-256을 확인합니다(다른 데이터면 학습 중단)

## 5. 학습 모델 설계·실행 [매뉴얼 6]
- 학습 플랫폼 > 학습 모델 설계
- 학습 모델명: `PressGuard_v1.2_full`
- 학습 데이터: **데이터셋** 옵션 → 돋보기 → `KAMP_소성가공_유압펌프` 선택
- 문제 유형: Classification / 알고리즘: `PressGuard_HGB_v1.2` / 평가 방법: **None**
  - 분할(마지막 20% 시험)·교차검증을 코드가 직접 하므로 플랫폼 분할은 쓰지 않습니다
- 상세 설계: 리소스는 CPU 2코어·메모리 4Gi 이상 권장(GPU 불필요) → 저장
- 학습 모델 관리 > 해당 모델 > **실행** → 상태 '수행중' → '완료'(약 2~4분)
- 확인할 것(학습상태 탭)
  - 지표: accuracy 0.980, precision 0.683, recall 0.719, **f1 0.700**, ap 0.847, roc_auc 0.981, persistent_alarm_f1 0.767
  - 결과 파일: `platform_check.txt` 첫 줄이 `test decisions/alarms identical to submitted results: True`
  - 그림: model_comparison.png, validation_design.png, test_performance.png, error_conditions.png 등
- 로그에 `bundle mode`가 보이면 학습 패키지가 없는 실행환경입니다 → 2단계 빌드를 확인하세요(그래도 제출 모델로 배포는 가능)

## 6. 추론 모델 배포 [매뉴얼 6 · 7]
- 학습 완료 화면에서 **모델 배포** → 추론 모델명 `PressGuard_v1.2_infer` → 배포
- 추론 플랫폼 > 추론모델 관리 > 서비스 시작(CPU 1코어·메모리 1~2Gi면 충분)
- 추론은 scikit-learn 없이 표준 라이브러리 엔진(pumpguard)으로 동작 → 현장 EXE와 같은 점수·판정

## 7. 추론 테스트 [매뉴얼 7]
- JSON 테스트: 입력창에 `4_추론테스트/추론테스트_입력창용.txt` 내용을 붙여넣기(시험 이상 구간 12행)
  - 기대 결과: `alarm_events: 1`, 상태가 `WARMUP, WARMUP, WATCH, ALARM ×9`
  - 형식: `[["시각", AI0, AI1, AI2], ...]` 시간순 4행 이상. 5번째 값으로 모드 지정 가능(`"unmanned"` 등)
  - 반드시 큰따옴표(") JSON. 작은따옴표 입력은 플랫폼 파서가 오류를 냅니다
- 파일 테스트: `파일_추론_예시_anomaly_test.csv` 업로드 → 행별 결과 CSV + 요약 JSON(zip) 반환
- 추론 API(선택): 추론 API 관리 > 신규등록 → 데이터 형식 JSON 또는 파일 → 위 추론 모델 연결

## 8. 보고서·발표에 쓸 문장(선택)
- "제출 코드를 KAMP dl 플랫폼(T3Q.ai)에 학습 알고리즘·실행환경으로 등록해 데이터셋 → 학습 → 추론 배포까지 재현했으며, 플랫폼 학습 결과의 시험 판정·경보가 제출 결과와 동일함을 확인(platform_check.txt)"
- 플랫폼 화면 캡처 2장(학습상태 지표, 추론 테스트 결과)을 보고서 6장 또는 발표 14번 슬라이드에 추가하면 좋습니다

## 문제 해결
| 증상 | 원인·조치 |
|---|---|
| 빌드 실패: 이미지 pull 오류 | 외부 이미지 차단 → planB_python310, 그래도 실패하면 플랫폼 기본 General 이미지 + `train_mode=bundle`(추론만 배포) |
| 학습 오류: CSV를 찾지 못함 | 데이터셋에 두 CSV(또는 zip)가 있는지 확인. 데이터셋 없이도 알고리즘 zip 안의 data/로 학습됨(학습 데이터 '사용안함' 선택 가능) |
| 학습 오류: SHA-256 불일치 | 원본과 다른 CSV. press_dataset.zip을 다시 업로드 |
| 그림의 한글이 네모 | Dockerfile의 fonts-nanum 줄 누락 |
| 추론 응답 `cannot access local variable 'test_data'` | 입력이 JSON이 아님(작은따옴표 등). 큰따옴표로 다시 입력 |
